The service

Issue Templates lets a Jira site save an issue tree as a template and apply it in one step. Before creating anything it checks the template against the target project's current issue types and create-screen fields, and if any step of an apply fails it deletes what that apply created and reports what it removed. The app does its work by calling the Jira API as the user who applied the template, with that user's permissions.

What we promise, stated plainly

  • An apply that cannot complete is rolled back and reported; the app is designed so that a template never leaves an orphaned child issue behind.
  • A template that no longer matches the project's screens is refused before anything is created.
  • Data stays inside Atlassian's Forge platform. See our Privacy Policy.

What we do not promise: that every possible Jira configuration is supported (v1 covers Jira Cloud, trees up to four levels, and apply from an existing issue or the template library), or that Jira itself will accept every create the template asks for — permission schemes, required custom fields, and workflow validators are the site's, and a create Jira refuses is reported back to you rather than hidden.
