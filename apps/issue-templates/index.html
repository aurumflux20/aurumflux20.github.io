Issue Templates by AurumFlux

Documentation · Jira Cloud · built on Atlassian Forge

Save an issue and its whole child tree as a template, then apply it in one click. Every apply is checked against the target project's current configuration before anything is created, and is undone whole if any step fails.

Install

Install from the Atlassian Marketplace listing. The app adds an Issue Templates page under Apps in your Jira site, and a project-scoped page inside each project.

It asks for three permissions: read Jira work, write Jira work, and app storage. It makes no network calls outside Atlassian.

Create a template

Open Apps → Issue Templates and fill the New template form.

FieldWhat it does
NameHow the template appears in the library. Must be unique.
ScopeGlobal (every project), Project (one project, set the key below), or Personal (only you).
Project keyOnly used when scope is Project, e.g. ENG.
CategoryA free-text label shown next to the template, e.g. Delivery.
Root issue typeThe issue type of the top issue, exactly as the project names it, e.g. Epic or Task.
Root summaryThe top issue's summary. May contain variables.
DescriptionOptional description for the top issue. May contain variables.
ChildrenThe tree, one issue per line. See below.
VariablesComma-separated names you will be asked for at apply time.

Writing the child tree

One issue per line, in the form Type: Summary. Indent two spaces for each level down. Up to four levels.

Task: Cut release branch {{version}}
  Sub-task: Freeze main and tag {{version}}
  Sub-task: Run migration dry-run
Task: Verify on staging
  Sub-task: Smoke-test the checkout path
Task: Ship to production

The type name must match the project's own name for that issue type. Sub-task and Subtask are different strings, and a project that calls it one will refuse the other. The app tells you which name it expected rather than guessing.

Variables

Write {{name}} anywhere in a summary or description, and list name in the Variables field. At apply time you are asked for a value for each one, and every occurrence is replaced before the issue is created.

Apply a template

Open the template library, choose a template, enter the target project key and any variable values, then apply. What happens, in order:

  1. The template is checked first. The app reads the project's current issue types and create-screen fields. If the template asks for an issue type or a field the project no longer has, the whole apply is refused and it names what does not match. Nothing is created.
  2. The tree is created top down, parents before children, and each new issue key is recorded as it is made.
  3. If any create fails, every issue that apply already created is deleted, children first, and the result lists what was removed. Anything that could not be removed is named rather than hidden.
  4. If you apply twice, the second attempt returns the first result instead of building a second tree. An attempt still running is reported as in flight rather than duplicated.

Editing and deleting

Use Edit in the library to change a template in place, and Delete to remove it. Deleting a template does not touch issues that were created from it. Uninstalling the app removes all of its stored data for that site.

What v1 does not do

  • Applying from inside Jira's global issue-create dialog. Planned, not shipped.
  • Trees deeper than four levels.
  • Copying attachments, comments, links, or custom field values from a source issue. Templates carry issue type, summary, and description.
  • Jira Data Center or Server, and Confluence. Jira Cloud only.

Permissions and what Jira will still refuse

The app calls the Jira API as the person applying the template, with that person's permissions. If a project's permission scheme, a required custom field, or a workflow validator blocks a create, Jira refuses it and the app reports that refusal back to you and rolls the apply back. It does not work around your site's configuration.

Data and privacy

Template definitions and a short record of each apply are held in Forge storage inside Atlassian's infrastructure. An account ID is stored only for personal-scope templates, so that only you see them. Nothing leaves Atlassian's platform. Full detail is in the privacy policy; the terms of service cover the rest.
