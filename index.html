once-kernel

The idempotency kernel. Exactly-once execution under real concurrency, with receipts that prove what ran — plus a hash-chained ledger an outsider can verify without trusting you.

live npm i once-kernel TypeScript · Python

effectfence

An MCP server that fences side effects at the agent edge: prepare, commit, abort. Written in Rust, ships as a single binary for four platforms.

fencescan

Points at any codebase and reports tool calls that could fire the same effect twice. Evidence and candidates — never a verdict, because an outsider usually can't prove a double-fire from code alone.

live npx fencescan GitHub

Being built — honest status

  • building Provider Truth Atlas — measured, not assumed: what real providers actually do when you retry. Resend measured; the rest marked unknown until tested.
  • building The Retry Contract — a per-tool declaration of retry behaviour, proposed as a superset of MCP's existing hints. Draft RFC, holes welcome.
  • researching Settlement ledger for teams — org-wide evidence of what agents did to the world. Design stage; nothing shipped.

Nothing above is sold, promised, or dated. When something ships it moves up to the list that has an install command under it — that's the only promotion criterion we use.

Research

We scanned 671 MCP servers to see what happens when an agent retries

80% perform real writes. Of those, 32% have no visible idempotency guard. 35 touch money with no guard we could find. Published with aggregates only, no names, failed lookups excluded rather than counted as zeros — and a section on what a scanner fundamentally cannot see.
